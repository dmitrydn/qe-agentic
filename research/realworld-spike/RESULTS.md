# RealWorld (Conduit) measurement spike: RESULTS

Run date 2026-10-23. This is a measurement spike. Nothing was fixed. No file under any `realworld/specs/` folder or any implementation's source was edited (verified with `git status` at the end; the one modified file in a clone is `react/public/mockServiceWorker.js`, regenerated by `yarn install`'s MSW postinstall, not by me).

## 1. Verdict

- **Does it run: yes.** Nitro backend: Hurl suite 13/13 files, 154 requests, 692 assertions, all green. The README's "spec-compliant" claim is **not stale** for the Hurl suite.
- **Best frontend: Angular** (`realworld-apps/angular-realworld-example-app`): **133/139** passed (95.7%) in the suite's default `API_MODE=true`. The 3 social failures were missing demo data (`johndoe`) and pass after seeding (targeted rerun, 6/6), giving **136/139** (97.8%, partly inferred). Vue 118/139 (84.9%), React-FSD 41/139 (29.5%).
- **Ready for Phase 1: conditional.** Conditions: (a) use Angular + Nitro with `API_MODE=true` and a seeded `johndoe` user; (b) Angular hardcodes the hosted API URL, so it needs a host-remap workaround that I built outside the repo; (c) the "128 tests" figure is wrong (suite has 139); (d) the requirements baseline needs correction before it is frozen as ground truth (Step 4).

### Step 3: Ownership probe against local Nitro (spec silent, G-01)

Raw log with every request and body: `logs/step3-ownership.log` (tokens redacted). Fresh database. Users A and B registered (201 each); A created an article (201, slug `Owned-by-A-1792762533-ecd87236`) and a comment (201, id 1).

| Request (by B unless noted) | Status | Body |
|---|---|---|
| `PUT /api/articles/{A's slug}` `{"article":{"body":"tampered by B"}}` | **403** | `{"errors":{"article":["forbidden"]}}` |
| `GET` A's article afterwards (as A) | 200 | body still `"original body"`, `updatedAt` unchanged |
| `DELETE /api/articles/{A's slug}/comments/1` | **403** | `{"errors":{"comment":["forbidden"]}}` |
| `GET` A's comments afterwards (as A) | 200 | comment id 1 still present |
| `DELETE /api/articles/{A's slug}` | **403** | `{"errors":{"article":["forbidden"]}}` |

**Interpretation (separate from the numbers).** The reference backend does enforce ownership at the API level and returns 403 with the resource type as the error key, matching the description at `openapi.yml:792` ("The error key identifies the resource type"). The prose spec says nothing about who may update or delete, but `openapi.yml` declares 403 on those three operations (lines 275, 302, 385). So G-01 as written ("nothing says another user's DELETE must fail") overstates the silence; see Step 4.

### Step 4: Independent requirements recount

Full list and comparison: `requirements-recount.md` (written before opening the baseline; comparison appended after, clearly marked).

| | Baseline v0.1 | Independent recount |
|---|---|---|
| Atomic requirements | 73 | **210** |
| Gaps | 11 | 22 |

- **Why the difference:** the baseline cites `openapi.yml` in no requirement (about 105 of mine are OA status-code and schema rules), merges auth+outcome into one row, and covers only the header part of the templates (I extracted all pages, plus styles, tests and API docs).
- **In baseline, not recount:** R-031 ("Slugs shall be unique; duplicate titles shall produce distinct slugs", cited EP L185). No source says this (`grep -i 'unique|distinct'` over backend docs and OA: no hits; EP L185 is the heading "### Delete Article"). It breaks the baseline's own "stated only" rule. Also R-010/R-037 are out-of-scope statements, not observable behaviours.
- **Citations:** baseline line numbers are correct up to EP L183, then +2 for the rest of `endpoints.md`, ±1 in routing/templates, and G-11 cites `frontend/api.md L205–208` in a 34-line file (actual L31–34).
- **Baseline gaps found independently:** 8 of 11 (G-01, 02, 03, 06, 07, 08, 09, 10) fully; G-04 only in the narrower sense that the prose is silent; G-05 only partly (I logged the related optional-auth contradictions but missed the specific `favorited`/`following` point; I agree it is real).
- **Baseline gaps I think are wrong:**
  - **G-04** (success codes unspecified): `openapi.yml`, an allowed source, gives 200/201/204 per operation.
  - **G-03** (login failure unspecified): it is a conflict, not a silence. OA says 401 (`openapi.yml:34`), `error-handling.md:7` says 422 for validation.
  - **G-01** (no ownership rule): overstated, because OA declares 403 on article PUT/DELETE and comment DELETE; the missing piece is the *condition* for the 403. Step 3 also shows the reference backend enforces it.
  - **G-02** (no validation rules): the "uniqueness" sub-claim is wrong (OA declares 409 `has already been taken`). The `maxLength/pattern` claim is correct (only two `minimum:` hits in OA).
  - **G-11** (hosted API deviates): a deployment note, not a requirements gap; mis-cited.
- **Gaps in recount not in baseline** (examples): error-message wording conflict ("can't be empty" vs "can't be blank"), slug collision rules, follow/favorite edge cases, cascade on delete, `PUT /user` conflicts, markdown sanitisation, template CDN assets vs shared `styles.css`.

**Interpretation.** Two readers following the same rules on the same sources produced materially different counts (73 vs 210) and different gap sets. Scope of sources and the atomic-split policy drive the number, so the raw count is not a stable metric. The "freeze section 4 as ground truth" plan is unsafe until at least G-01, G-03 and G-04 are corrected and R-031 is removed.

`runner/tls-proxy.mjs` (Angular only; run with `node tls-proxy.mjs` from `runner/`):

```js
import https from 'node:https'; import http from 'node:http'; import fs from 'node:fs';
const target = { host: 'localhost', port: 3000 };
https.createServer({ key: fs.readFileSync('key.pem'), cert: fs.readFileSync('cert.pem') }, (req, res) => {
  const p = http.request({ ...target, method: req.method, path: req.url, headers: { ...req.headers, host: 'localhost:3000' } },
    (r) => { res.writeHead(r.statusCode, r.headers); r.pipe(res); });
  p.on('error', (e) => { res.writeHead(502); res.end(String(e)); });
  req.pipe(p);
}).listen(8443);
```
