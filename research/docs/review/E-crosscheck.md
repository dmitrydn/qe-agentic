## 2. Overstated or unfair findings in A–C

- **"4 of 9 catches from one test"** (A L-14, B C2). It is 3 from one test, or 4 from one curated hint across two tests.
- **"2 labels relabelled"** (A L-10/L-11/§3.2). It is 3 (C is correct).
- **"$0.05 off by 1–2 orders of magnitude"** (A I-08, L-17). The scope differs: 4 vs 44 requirements. Per requirement the gap is ~7×, and "per curated run" is literally true. The real criticisms are that it is an all-pass run with no triage, and that it is a different run from the headline scorecard.
- **B C1 "8/12 and 14/16 leak, cannot be treated as measurements".** The triage leak is confirmed, but it does not touch the 4 live real-defect cases. The environment cases are decided by their evidence anyway. The testability ids encode the gap kind rather than the verdict, and one points the wrong way. Weakened evidence, not zero evidence. The few-shot duplication (2 cases) is the cleanest contamination finding.
- **A: "the deck never mentions Stage 10" / "Under-reported negative result".** The deck is dated "June 2026" (`pptx.md:8`). Stage 10 ran 2026-07-21 (s10 file mtimes). The deck cannot have reported it, so this is a valid criticism only if the deck is being presented now without an update. The omission from PROGRESS.md is a fair criticism.
- **A L-07 "Platform = no AI CONTRADICTED".** B (row 31) confirms "LLM rates, code decides" is genuinely in code for testability. The fair point is narrower: the FP gate and release gate consume LLM triage labels.
- **A L-22, "sdlc-flows.md says not yet built" as evidence that Operate is not done.** That doc header is stale. `ops/sync-requirements.js` and `ops/validate-release.js` and `workflow/steps/release.js` exist. "No verification record" is the fair criticism.
- **A L-21 "negative controls cannot fail in either direction".** An unexpected catch is reported, though it does not fail the gate. "Constrain little" is fairer than "nothing".
- **C/A "the whole grounding drop comes from removing 3 requirements" framed as a flaw.** Removing ungrounded requirements is the gate's intended effect. The flaw is the n = 1 decision and the claim of signal beyond noise.
- **Credit the project already earned (disclosed by the project itself):**

  - the triage first-run miss and fixture edits (VERIFICATION :631-664);

## 3. Important issues all reviewers missed

1. **Triage battery silently drops non-FAIL cases from the denominator.** At `eval/run-triage-battery.js:83-92`, any case whose live run does not FAIL (`predicted === null`) is put in `unscored` and excluded from accuracy. A real-defect injection that the test fails to trip, or a "bad test" that passes, cannot count as wrong. So "12/12" can only be ≤ 12/scored, and the 6 live cases are self-selecting. The final run is not persisted, so whether all 12 were scored cannot be verified.
2. **The triage "fix" gave Triage the same hint that encodes the defect oracle.** After WS-D, triage sees `requirement.apiHints` (`prompts/triage.user.md:8-14`), which for TX-007 states the ×100 and balance rules. The headline demo's triage quote ("documented dollar-to-cents conversion", MAKE-THE-CASE:60) is triage re-reading the hint, not independent reasoning. A mentions evaluator diversity, but nobody connects it to the demo quote.
3. **The reviewers' own statistics ignore clustering by requirement** (see #17). Per-test CIs on 24/132 or 15/123 are too narrow. The project's Stage 10 design (paired by requirement) is more correct than A's and C's comparisons.
4. **A second substitution failure exists besides `:param`.** The worksheet shows a literal `{J5Fd3dlBEBu}` sent as a transaction id (`reports/s10/worksheet.md`, COMMENTS-002-negative-001): a resolved capture left wrapped in single braces. A and C cite the row but treat it as a triage error. It is a separate runner/template bug class that also inflates "defects".
5. **Model retirement is a re-baseline obligation, not just a reproducibility note.** The config default (`config.js:32`) points at a model that retires 2026-11-30. Every frozen number (catch, FP, testability, triage) must be re-measured on the replacement before any further leadership use. D raises the retirement but not that all A/C recomputations become historical.
