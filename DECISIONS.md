# Decisions

The single list of project decisions made after intent v2. Other files link here instead of restating them. Founding decisions (2026-10-20) remain in `intent.md` §10.

**Owner:** Dmitry · **Format:** one row per decision; when a decision changes, mark the old row `Superseded by D-nn` and add a new row.

| ID | Question | Decision | Consequence | Status · date |
|---|---|---|---|---|
| D-01 | Which apps does the Phase 1 demo run on? | **RealWorld (Conduit) only.** No Java app in Phase 1 | Phase 1 shows the capabilities on one stack (TypeScript). The "works on any stack" claim is designed for (connectors) but not demonstrated until Phase 2. Optional follow-up, not scheduled: check whether a Java RealWorld backend that passes the same API suite could serve as a second stack at low cost | Decided · 2026-11-17 |
| D-02 | Remove the examples from `openapi.yml` before agents read it? | **No, keep them.** The file has 5 examples, all error-response bodies (e.g. `token: "is missing"`, `username: "has already been taken"`). They are the only place the specification states error wording, they come from the specification authors (P2), and the backlog cites them | `openapi.yml` stays an agent-readable requirement source, unmodified | Decided · 2026-11-17 |
| D-03 | How are Conduit's official test suites (the held-out oracle) kept away from agents? | **Four measures together:** (1) agent workspaces get the specification by sparse checkout without `specs/api/hurl`, `specs/api/bruno`, `specs/e2e`; the full install with the suites lives in `~/realworld-sandbox` and is never opened in the agent's workspace; (2) agent terminal commands are approved by a person (no auto-approve); (3) every agent run hands back the list of files and URLs it read, and the person checks it before accepting the output; (4) eval scores rest mainly on planted problems; results against the official suites are secondary and labelled "possibly memorised" (the suites have been public for years and may be in model training data) | Measures 1–3 stop accidental and casual reads; measure 4 is the only defence against memorisation. Deliberate reads are not prevented, only detected by (3) | Decided · 2026-11-17 |
| D-04 | Who reviews the derived BA backlog and answers its open questions? | **A QES tester from the bench is assigned the BA role for Conduit.** Their answers are the business decisions for this app. Starts as soon as the agent has produced the review-ready requirements | For each open question the BA either confirms what the specification implies, or sets a rule the app does not meet; the latter must be tagged as a known requirement-vs-system gap. Expect half a day to a day of judgement work. Name and start date to be added when assigned | Decided (person not yet named) · 2026-11-17 |
| D-05 | Where does the BA check decisions against the app (`REVIEW-GUIDE.md` step 4)? | **The team's Azure instance** (`docs/handover/2026-11-17-realworld-sandbox/02-sandbox-architecture.md` §4a), not a local install | The BA never has the official test suites on their machine (supports D-03). The instance's deployed commits are not yet recorded, and its data is lost on redeploy | Decided · 2026-11-17 |
| D-06 | How are business rules separated from technical interface detail in the Conduit requirements? | **Two layers.** **BR** (business rule): a condition and an outcome that matters to a user or the business, even if it names a status code or message. **IC** (interface contract): items that only list declared status codes, schema fields or types, request/response shapes, markup or CSS classes, or fixed static text. IC items stay cited and traced and are used by C1/C2, but the BA does not review them. Mixed items stay BR | Run 2b reclassifies all rules by this test; moved rules get IC IDs and the old BR IDs are retired and logged. **The agent classifies on its own judgement; IC content is not human-reviewed.** Guard against hiding a business decision: the agent lists every rule it moved to IC that mentions an actor, permission, limit or condition, and Dmitry checks only that list | Decided · 2026-11-18 |
